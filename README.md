# الشرماني سوشيال — Sharmani Social (MVP)

منصة ويب عربية متعددة العملاء لإدارة الحسابات، الاشتراكات، الوسائط، النشر والجدولة.

## التشغيل

1. ثبّت Node.js 20 أو أحدث.
2. نفّذ `npm install`.
3. انسخ `.env.example` إلى `.env`.
4. ضع `JWT_SECRET` عشوائيًا وطويلًا (32 حرفًا على الأقل).
5. نفّذ `npm start` ثم افتح `http://localhost:3000`.

## الوظائف المنفذة

- تسجيل وإنشاء حساب بكلمة مرور مشفرة bcrypt وJWT.
- فصل بيانات العملاء عن بعضهم، وتحديد عدد الحسابات والمنشورات بحسب الخطة.
- رفع وسائط إلى تخزين محلي خاص (100MB لكل ملف).
- اختيار الحسابات وإضافة مهام للنشر الفوري أو المجدول.
- عامل نشر يعمل كل 10 ثوانٍ، ونتائج مستقلة لكل حساب.
- نشر حقيقي إلى **قنوات Telegram فقط** باستخدام Bot API عند ضبط `TELEGRAM_BOT_TOKEN` وإضافة البوت مسؤولًا في القناة. أدخل `@channel` أو رقم chat ID عند إضافة الحساب.
- بقية المنصات هي حسابات انتظار وليست OAuth متصلة؛ يسجل النظام فشل التسليم بوضوح ولا يدعي النجاح.
- عرض خطط وأسعار نموذجية وطلب اشتراك تجريبي، **دون تفعيل الدفع أو ترقية الاشتراك**.

## قيود النسخة الحالية

- ليس منتجًا جاهزًا للإطلاق العام. يحتاج بوابة دفع موثقة، إدارة فواتير وضرائب، تحقق بريد، استعادة كلمات مرور، سياسة خصوصية وشروط خدمة، إدارة موافقات OAuth، تدوير وتشفير رموز الوصول، فحص محتوى الملفات، حماية CSRF بحسب أسلوب الجلسات، مراقبة، نسخ احتياطية، إدارة فرق، عامل مهام موزع، تخزين كائنات سحابي، وفحص أمني.
- صلاحيات TikTok وMeta وYouTube وX وغيرها تتطلب تسجيل تطبيقات ومراجعات وامتثالًا لشروط المنصات. لا تستخدم كلمة مرور العميل بديلًا عن OAuth.
- بيانات الاشتراك مخزنة لكن طلب الخطة لا يغيرها ولا يحصّل المال.
- حدود الخطة على عدد المنشورات محسوبة على آخر 30 يومًا، لا على شهر تقويمي.
- ملفات MOV وMP4 وغيرها يجب تحويلها وفق شروط المنصة عند توسيع النشر.
- ينصح بـ PostgreSQL وRedis/queue وتخزين S3 وHTTPS عند الانتقال للإنتاج.

## API

`POST /api/auth/register`, `POST /api/auth/login`, `GET /api/me`, `GET /api/plans`, `POST /api/subscription/request`, `GET|POST /api/accounts`, `DELETE /api/accounts/:id`, `POST|GET /api/media`, `GET /api/media/:id/file`, `GET|POST /api/posts`, `GET /api/posts/:id/deliveries`.

## أمن

لا تضع أسرارًا في الكود أو المستودع. استخدم HTTPS عند النشر. استعمل مفاتيح منفصلة للتطوير والإنتاج. بيانات SQLite والوسائط في مجلد `data/` الذي ينبغي استبعاده من Git.
